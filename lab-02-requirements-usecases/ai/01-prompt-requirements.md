# Завдання: Генерація вимог (EARS), сценаріїв (User Stories, Gherkin), Use Case діаграми та матриці трасування

## Мета
На основі технічної специфікації `spec.md` розробити первинний комплект артефактів вимог та прецедентів використання для системи **Billiard CRM**.

## Вхідні дані
- Специфікація та критерії прийняття: `spec.md`
- Опис завдання: `TASK.md`
- Правила роботи: `AGENTS.md`

## Вимоги до результату
1. **EARS-вимоги (`requirements.md`)**:
   - Сформулювати функціональні та нефункціональні вимоги за всіма основними шаблонами EARS (Ubiquitous, Event-driven, State-driven, Unwanted behaviour, Optional).
   - Використовувати ключові слова великими літерами (`КОЛИ`, `ПОКИ`, `ЯКЩО... ТО`, `ДЕ`, `ПОВИННА`).
   - Включити наскрізну вимогу контролю доступу та щонайменше 1 непокриту вимогу (out-of-scope) з поясненням.
2. **User Stories та Gherkin-сценарії (`requirements.md`)**:
   - Написати User Stories для основних ролей (`User`, `Player`, `Captain`, `Organizer`, `Admin`).
   - Розписати повнотекстові Gherkin-сценарії (`# language: uk`, `Given/When/Then`, `Rule`, `Scenario Outline` + `Examples`) для критичних бізнес-процесів.
3. **Матриця трасування (`requirements.md`)**:
   - Побудувати Markdown-таблицю «вимога-id ↔ сценарій/UC» зі зв'язками багато-до-багатьох (M:N).
   - Позначити непокриті вимоги/UC.
4. **Use Case діаграма (`model.mmd`)**:
   - Побудувати діаграму в синтаксисі Mermaid (`flowchart LR`) із межею системи (`System Boundary`), усіма акторами зі `spec.md`, ієрархією узагальнення (`Player --|> User`, `Captain --|> Player`, `Admin --|> Organizer --|> User`), зв'язками `<<include>>` та `<<extend>>`.
